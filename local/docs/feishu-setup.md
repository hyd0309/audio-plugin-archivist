# 飞书配置与联调

在本地设置页 http://127.0.0.1:8765/#settings 填写凭证。不要在聊天中发送 App Secret 或授权令牌。

## 准备应用与目标

1. 在 [飞书开发者后台](https://open.feishu.cn/app) 使用自己的自建应用。若你原工作流使用的就是自己的应用，可在权限适合的前提下复用；Coze 官方插件内部凭证无法导出替代。
2. 应用需具备用户身份的文档读取、创建、编辑，以及云空间素材上传等权限。当前授权请求默认 scope 为 `docx:document drive:drive offline_access`，必须与应用已开通并生效的权限匹配；`offline_access` 用于保持授权。按后台要求让权限及版本配置生效，并使当前账号处于应用可用范围。
3. 在应用的安全设置中添加完整回调地址：`http://127.0.0.1:8765/api/feishu/callback`。主机名、端口与路径要与本地设置一致。
4. 选一个有编辑权的详情文件夹，以及一篇有编辑权的新版飞书汇总文档。可以沿用原目录与汇总；这次联调会新增一个 Chorus 条目。
5. 设置页分别填入 App ID、App Secret、文件夹 `/folder/` 链接和汇总 `/docx/` 链接。Wiki 地址不能直接作为 docx ID 使用，应取得底层新版文档链接。
6. 点击“保存设置”，然后“用飞书账号授权”。在飞书确认授权后回到本地页面，看到“飞书授权完成”即可返回工作台。
7. 点击“检查连接”。这一步只确认能读取汇总文档，不会创建内容，也不能独立证明目标文件夹可写。

## 实际归档验证

## 用户身份与应用身份

多维表格接口支持 `user_access_token` 与 `tenant_access_token`，并非必须使用用户身份。当前实现沿用个人 OAuth，代表授权用户操作其有权访问的资源，适合在用户指定的个人文件夹内归档。

应用身份同样可行，但需要在应用身份页签开通对应 API 权限，并让应用本身获得目标文件夹、文档、表格的资源权限。单独开通 API 权限不代表自动获得用户全部文件的访问权。应用身份创建的表格默认归应用所有，用户的编辑管理权限需要另行配置；具体行为以创建位置与实际权限设置为准。当前适配器实现的是用户 OAuth，切换应用身份需要增加独立的令牌获取、缓存和资源权限验证，不能只在后台勾选另一页签。

新增 `bitable:app` 后，需要从本地“授权多维表格”入口重新同意授权，使新增权限进入用户凭证。只发布应用权限或从旧链接登录，不能保证现有凭证包含新增范围。

参考：[官方建表教程（支持两种身份）](https://open.feishu.cn/document/introduction-2?lang=zh-CN)、[新增记录（两种身份均需编辑权限）](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create)。

## 归档检查项

在 Chorus 档案详情点击同步，完成后检查：

- 详情文档位于指定文件夹，标题正确，正文与本地说明相符。
- 汇总末尾出现六字段中的摘要字段与完整界面图。
- 详情的原生云文档引用可以打开正确文档。
- 再次点击同步不会重复追加相同条目。

“文档预览块”属于可选模式；它依赖飞书租户对该块类型的创建支持。默认原生提及已经是云文档引用，但不保证外观等同 Coze 原工作流的嵌入块。

## 出错时

- 授权页提示回调不匹配：核对后台和本地设置中的完整回调地址。
- 授权页提示权限无效或应用不可用：核对用户身份权限、应用发布状态和可用范围。
- 能授权但不能写入：核对目标目录、文档的编辑权及相关 API 权限。
- 提示“写入结果不确定”：查看云端是否已产生内容。程序保留 `sync/*.json`，不会自动再次新建；不要删除或随意重置这些记录。
- 显示已过期：从设置页重新授权。程序不会把令牌输出在界面或错误信息中。

实现参考：[用户访问令牌](https://open.feishu.cn/document/authentication-management/access-token/get-user-access-token)、[上传素材](https://open.feishu.cn/document/server-docs/docs/drive-v1/media/upload_all) 和 `docs/reference/` 中留存的官方 SDK 模型。网页文档部分内容依赖动态加载，实际租户权限和接口返回仍需联调核实。
